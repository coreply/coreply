# Coreply Cloud

## Authentication setup

Google and GitHub sign-in use Better Auth in the Hono Worker, using Drizzle and D1. `/demo`
requires a session. `/api/auth/*` stays public; all other `/api/*` routes verify
the session on the backend. Cached frontend state never authorizes API requests.

### Server environment

Copy `.dev.vars.example` to `.dev.vars` in this package and set:

| Variable | Value |
| --- | --- |
| `BETTER_AUTH_SECRET` | Random secret, at least 32 characters. Generate with `openssl rand -base64 32`. |
| `BETTER_AUTH_URL` | Backend origin, e.g. `http://localhost:5173` locally, your HTTPS origin in production. |
| `GOOGLE_CLIENT_ID` | Google **Web application** OAuth client ID. |
| `GOOGLE_CLIENT_SECRET` | Secret for that Web OAuth client. Server only. |
| `GITHUB_CLIENT_ID` | GitHub OAuth app client ID. |
| `GITHUB_CLIENT_SECRET` | GitHub OAuth app client secret. Server only. |
| `CLOUD_WEB_ORIGIN` | Exact browser frontend origin. Use `http://localhost:5173` for this frontend or `http://localhost:8081` for Expo web. |

Register these Google Web OAuth redirect URIs:

- `http://localhost:5173/api/auth/callback/google`
- `https://YOUR_CLOUD_HOST/api/auth/callback/google`

Create GitHub OAuth apps for development and production, with callback URLs
`http://localhost:5173/api/auth/callback/github` and
`https://YOUR_CLOUD_HOST/api/auth/callback/github`, respectively.

For production, set each variable with `pnpm exec wrangler secret put NAME`.
This frontend is same-origin. Optionally set `VITE_COREPLY_CLOUD_CALLBACK_URL`
in `.env` to choose the post-sign-in destination, as shown in `.env.example`.
It defaults to `/`, which redirects signed-in users to Usage.

### Database

The `DB` D1 binding is configured in `wrangler.json`. Local D1 needs no Cloudflare
account or database ID. Initialize it before logging in:

```sh
pnpm db:migrate:local
pnpm dev
```

Before deploying, create the production database with
`pnpm exec wrangler d1 create coreply-cloud`, add its returned `database_id`
to the `DB` entry in `wrangler.json`, and run `pnpm db:migrate:remote`.
No remote database or deployment was created by this change.

The auth schema and initial SQL migration were generated by the official Better
Auth and Drizzle CLIs. To regenerate after changing auth's schema options:

```sh
pnpm auth:generate
pnpm db:generate
pnpm cf-typegen
```

`auth-schema.config.ts` is the Node-only CLI configuration using Wrangler's local
D1 proxy. Keep schema-affecting plugins/options aligned with `src/worker/auth.ts`.
Runtime exports one `auth` instance using `cloudflare:workers` bindings.

### App environment and Google setup

Copy `../coreply-app/.env.example` to `../coreply-app/.env.local`:

| Variable | Value |
| --- | --- |
| `EXPO_PUBLIC_COREPLY_CLOUD_URL` | Backend origin reachable by the device/browser. Android emulator uses `http://10.0.2.2:5173`; a physical device needs your machine's LAN address. |
| `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` | The same Web OAuth client ID as the backend's `GOOGLE_CLIENT_ID`. Required on native. |
| `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` | iOS OAuth client ID. Required only on iOS. |

Never put `GOOGLE_CLIENT_SECRET` or `BETTER_AUTH_SECRET` in public app variables.
Rebuild the bundled Android app after changing its environment. The sign-in form
under API Provider → Coreply Cloud Preview shows a configuration message when
required app variables are absent. There is no separate account screen.

Android uses `react-native-nitro-google-signin`'s native branded button. Create
Android OAuth clients in the same Google project for the package and signing
certificate SHA-1: `app.coreply.coreplyapp.debug` for debug,
`app.coreply.coreplyapp` for release. Explicit Web client ID configuration means
no `google-services.json` or Google Services Gradle plugin is needed. Use an
emulator/device with Google Play services. Rebuild the native app after adding
the Nitro and SecureStore dependencies; Expo Go cannot run them.

For iOS, also register the iOS OAuth client's reversed-client-ID URL scheme in
the native app or Nitro's Expo config plugin before rebuilding. Follow the
[Nitro iOS setup](https://react-native-nitro-google-sign-in.github.io/docs/setup/ios).
The JavaScript client passes both configured IDs explicitly.

Shared sign-in UI receives the platform auth client through `CloudAuthProvider`.
The native button exchanges a Google ID token with Better Auth; the web button
starts Google's redirect flow. Native Better Auth stores cookies and cached
session data in SecureStore. Web uses browser cookies.

### Session and connectivity behavior

The UI uses Better Auth's `useSession()` directly, not a request on every route
change. Better Auth 1.7 preserves session data on network/server errors and
refetches after reconnecting. A successful empty session or a `401` removes
access to the demo. With no cached session and an unavailable server, the guard
shows a retry screen instead of assuming the user is signed out. Explicit native
logout clears the local session through the Expo plugin even if offline.

The conversations are still local demos, not live Cloud completions.

## Getting Started

To start a new project with this template, run:

```bash
npm create cloudflare@latest -- --template=cloudflare/templates/vite-react-template
```

A live deployment of this template is available at:
[https://react-vite-template.templates.workers.dev](https://react-vite-template.templates.workers.dev)

## Development

Install dependencies:

```bash
npm install
```

Start the development server with:

```bash
npm run dev
```

Your application will be available at [http://localhost:5173](http://localhost:5173).

## Production

Build your project for production:

```bash
npm run build
```

Preview your build locally:

```bash
npm run preview
```

Deploy your project to Cloudflare Workers:

```bash
npm run build && npm run deploy
```

Monitor your workers:

```bash
npx wrangler tail
```
